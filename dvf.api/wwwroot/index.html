Présentation

Les Données de valeurs foncières (DVF) sont publiées chaque année par l'administration fiscale française. Chaque ligne correspond à un bien immobilier ayant fait l'objet d'une mutation (vente, donation, échange…), telle qu'enregistrée par la Direction générale des finances publiques (DGFiP).

Pour chaque transaction, l'API restitue l'ensemble des 43 champs du jeu de données officiel, notamment :

  • la date et la nature de la mutation ;
  • la valeur foncière (valeur vénale supposée au jour de la mutation) ;
  • la localisation précise : commune, code postal, département, voie, section cadastrale, lots ;
  • les caractéristiques du bien : type de local (maison, appartement, terrain…), nombre de pièces principales, surface réelle bâtie, surfaces Carrez, surface du terrain.
Bon à savoir : les données sont fournies à des fins de recherche et de statistiques. Les valeurs indiquées sont des valeurs supposées : elles ne constituent pas une évaluation officielle d'un bien précis et peuvent différer du prix réellement payé (transactions entre proches, biens atypiques, etc.).

API

L'API est une API REST simple, sans authentification. Tous les paramètres sont vérifiés : toute requête invalide renvoie l'état 400 avec un message {"error": "..."}.

Routes

RouteMéthodeDescription
/api/mutations POST Interroge les transactions : filtres optionnels (combinaison ET) et pagination obligatoire.
/api/swagger GET Documentation interactive (Swagger UI).
/openapi/v1.json GET Spécification OpenAPI 3.1.

Requête — POST /api/mutations

Le corps JSON contient une liste filters facultative (chaque filtre est composé d'un field, d'un operator et d'un operand ; les filtres sont combinés par ET) et une pagination obligatoire : skip (nombre de lignes à ignorer, ≥ 0) et take (nombre de lignes à renvoyer, entre 1 et 1000). 

curl -s https://dvf-api.fr/api/mutations \
  -H "Content-Type: application/json" \
  -d '{
    "filters": [
      { "field": "Code postal",     "operator": "EQUALS",              "operand": 75001 },
      { "field": "Valeur fonciere", "operator": "GREATER_THAN",        "operand": 1000000 },
      { "field": "Date mutation",   "operator": "GREATER_THAN_OR_EQUALS", "operand": "2024-01-01" }
    ],
    "skip": 0,
    "take": 10
  }'

Réponse

{
  "rows": [
    {
      "Identifiant de document": "1001234",
      "Date mutation": "15/03/2024",
      "Nature mutation": "Vente",
      "Valeur fonciere": 1234000,
      "Code postal": 75001,
      "Commune": "Paris",
      "Type local": "Maison",
      "Nombre pieces principales": 5,
      "…": "… (43 champs au total par ligne)"
    }
  ],
  "pagination": {
    "totalRows": 4274,
    "page": 1,
    "pageSize": 1000,
    "totalPages": 5
  }
}

Le bloc pagination porte le nombre total de lignes correspondant aux filtres (totalRows), la page courante (page, à partir de 1), la taille de la page (pageSize) et le nombre total de pages (totalPages).

  • les noms d'opérateurs sont insensibles à la casse ;
  • sur la colonne Date mutation, l'opérande est accepté au format JJ/MM/AAAA ou AAAA-MM-JJ ; les opérateurs de plage comparent les dates dans l'ordre chronologique ;
  • avec LIKE, l'opérande est un motif SQL : les jokers % (zéro, un ou plusieurs caractères) et _ (un caractère) sont pris en charge, par exemple "%paris%".

Les données

Source : Données de valeurs foncières, jeu de données publié par l'État français (ministère chargé des comptes publics — Direction générale des finances publiques) sur data.gouv.fr.

  • années couvertes : 2021, 2022, 2023, 2024 et 2025 (≈ 20 382 915 transactions) ;
  • les données de l'État sont publiées avec un décalage d'environ un an après la fin de l'année considérée ;
  • chaque transaction expose les 43 champs du fichier officiel (identifiant, date et nature de la mutation, valeur, localisation cadastrale, caractéristiques du bien…).
